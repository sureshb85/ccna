Lab 08 - Access Control Lists (ACLs)

What is an ACL?

An access control list (ACL) is an ordered set of rules on a Cisco device that permits or denies traffic. A router or Layer 3 switch checks packets against those rules when an ACL is applied to an interface. ACLs are commonly used to control communication between VLANs, limit management access, and filter unwanted traffic.

How ACLs are evaluated: rules are checked from top to bottom. The first matching rule is used, then evaluation stops. Every ACL ends with an implicit deny any, so traffic not explicitly permitted is denied.

Core terms

TermMeaning
ACEAn Access Control Entry: one permit or deny rule inside an ACL.
Inbound ACLTraffic is checked as it enters an interface, before the device routes it onward.
Outbound ACLTraffic is checked just before it leaves an interface.
Wildcard maskA mask used in Cisco ACLs to identify which address bits must match. A 0 must match; a 1 is ignored.

Types of ACL

Standard ACLs

Standard ACLs filter only by the source IPv4 address. They are simple and suited to broad decisions, such as allowing one network while denying another. Because they cannot identify a destination, protocol, or port, they are normally placed close to the destination.

access-list 10 permit 10.1.1.0 0.0.0.255
access-list 10 deny any

Extended ACLs

Extended ACLs are more precise. They can match source and destination addresses, IP protocol (such as TCP, UDP, or ICMP), and TCP/UDP port numbers. They are used when a policy needs to permit or deny specific services—for example, allowing DNS but blocking web traffic. They are normally placed close to the source to stop unwanted traffic early.

access-list 100 deny tcp 10.2.2.0 0.0.0.255 10.1.1.0 0.0.0.255 eq 80
access-list 100 permit ip any any

Named ACLs

A named ACL uses a descriptive name instead of a number. It can be standard or extended. Named ACLs are easier to read and maintain, especially in larger configurations, and let you add or remove individual entries by sequence number.

ip access-list extended HR_TO_IT_POLICY
 deny ip 10.2.2.0 0.0.0.255 10.1.1.0 0.0.0.255
 permit ip any any

Numbered ACLs

A numbered ACL is identified by an ACL number. On current Cisco IOS, both numbered and named ACLs can be edited using ACL configuration mode. Named ACLs are usually clearer because the policy purpose is visible in the configuration.

ACL design rules

  • Write the most specific entries first; the first match wins.
  • Include explicit permit rules for traffic that must continue, especially before the implicit deny.
  • Use a named extended ACL for the upcoming inter-VLAN policy, because it clearly expresses the permitted and denied traffic.
  • Verify the ACL and its interface direction before testing: show access-lists and show ip interface.
