Lab 03 - VLAN Trunking and DTP

Objective

Build the five-switch topology shown, place eight PCs in VLANs 10, 20, 30, and 40, then carry those VLANs between the access switches and SW5. Practice both manually configured trunks and Dynamic Trunking Protocol (DTP).

Topology and cabling

 PC1 (VLAN 10) -- Gi0/2 SW1 Gi0/0 -- Gi0/3 SW5 Gi0/1 -- Gi0/0 SW2 Gi0/1 -- PC3 (VLAN 30)
 PC2 (VLAN 20) -- Gi0/1 SW1                    SW5 Gi0/2 -- Gi0/0 SW4 Gi0/1 -- PC7 (VLAN 30)
                                               SW5 Gi0/3 -- Gi0/0 SW3 Gi0/1 -- PC5 (VLAN 40)
                                                                    SW3 Gi0/2 -- PC6 (VLAN 20)
                                               SW2 Gi0/2 -- PC4 (VLAN 40)
                                               SW4 Gi0/2 -- PC8 (VLAN 10)

 Inter-switch links
 SW1 Gi0/0 <--> SW5 Gi0/0 : static trunk
 SW2 Gi0/0 <--> SW5 Gi0/1 : DTP (auto -- desirable)
 SW3 Gi0/0 <--> SW5 Gi0/3 : DTP (desirable -- desirable)
 SW4 Gi0/0 <--> SW5 Gi0/2 : static trunk

Note: The interface positions in the first two lines are written in connection order. Follow the explicit inter-switch table when cabling trunks; it is the authoritative mapping from the diagram. No router is present, so this is a Layer 2-only lab: hosts in different VLANs must not communicate.

Addressing and VLAN plan

Device  Interface  Address         VLAN
PC1     eth0       10.1.1.1/24     10
PC2     eth0       10.1.1.2/24     20
PC3     eth0       10.1.1.3/24     30
PC4     eth0       10.1.1.4/24     40
PC5     eth0       10.1.1.5/24     40
PC6     eth0       10.1.1.6/24     20
PC7     eth0       10.1.1.7/24     30
PC8     eth0       10.1.1.8/24     10

All PCs use the same /24 exactly as shown in the supplied topology. Do not configure a default gateway: there is no Layer 3 gateway in this lab.

Step 1 - Configure the PCs

For VPCS nodes, run the corresponding command at each PC prompt. The slash-length is the subnet mask; no gateway is supplied.

PC1> ip 10.1.1.1/24
PC2> ip 10.1.1.2/24
PC3> ip 10.1.1.3/24
PC4> ip 10.1.1.4/24
PC5> ip 10.1.1.5/24
PC6> ip 10.1.1.6/24
PC7> ip 10.1.1.7/24
PC8> ip 10.1.1.8/24

# Optional check on every VPCS node
PC1> show ip

Step 2 - Create the VLANs on every switch

VLANs are local to a switch unless VTP is deliberately configured. Therefore, run this block on SW1, SW2, SW3, SW4, and SW5. The names are descriptive only; the VLAN IDs determine membership.

enable
configure terminal
vlan 10
 name VLAN_10
vlan 20
 name VLAN_20
vlan 30
 name VLAN_30
vlan 40
 name VLAN_40
end
copy running-config startup-config

Step 3 - Configure access ports

Use switchport mode access so an end-device port cannot negotiate a trunk. Configure the following on each access switch.

SW1 - PC1 and PC2

enable
configure terminal
interface gi0/2
 description PC1_VLAN10
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
interface gi0/1
 description PC2_VLAN20
 switchport mode access
 switchport access vlan 20

end

SW2 - PC3 and PC4

Step 4 - Configure the trunks

For a static trunk, both ends are explicitly set to trunk. For the DTP links, use the requested negotiation modes. DTP is Cisco-proprietary and must be supported by the switch image; do not add switchport nonegotiate to either dynamic link.

SW1 to SW5 - static trunk

SW1# configure terminal
SW1(config)# interface gi0/0
SW1(config-if)# description STATIC_TRUNK_TO_SW5_Gi0/0
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk allowed vlan 10,20,30,40
SW1(config-if)# end

SW5# configure terminal
SW5(config)# interface gi0/0
SW5(config-if)# description STATIC_TRUNK_TO_SW1_Gi0/0
SW5(config-if)# switchport mode trunk
SW5(config-if)# switchport trunk allowed vlan 10,20,30,40
SW5(config-if)# end

SW2 to SW5 - DTP dynamic auto to dynamic desirable

SW2# configure terminal
SW2(config)# interface gi0/0
SW2(config-if)# description DTP_AUTO_TO_SW5_Gi0/1
SW2(config-if)# switchport mode dynamic auto
SW2(config-if)# switchport trunk allowed vlan 10,20,30,40
SW2(config-if)# end

SW5# configure terminal
SW5(config)# interface gi0/1
SW5(config-if)# description DTP_DESIRABLE_TO_SW2_Gi0/0
SW5(config-if)# switchport mode dynamic desirable
SW5(config-if)# switchport trunk allowed vlan 10,20,30,40
SW5(config-if)# end

Why it works: dynamic auto is passive, while dynamic desirable actively proposes trunking. Their combination negotiates a trunk. Auto-to-auto would not form a trunk.

SW3 to SW5 - DTP dynamic desirable to dynamic desirable

SW3# configure terminal
SW3(config)# interface gi0/0
SW3(config-if)# description DTP_DESIRABLE_TO_SW5_Gi0/3
SW3(config-if)# switchport mode dynamic desirable
SW3(config-if)# switchport trunk allowed vlan 10,20,30,40
SW3(config-if)# end

SW5# configure terminal
SW5(config)# interface gi0/3
SW5(config-if)# description DTP_DESIRABLE_TO_SW3_Gi0/0
SW5(config-if)# switchport mode dynamic desirable
SW5(config-if)# switchport trunk allowed vlan 10,20,30,40
SW5(config-if)# end

SW4 to SW5 - static trunk

SW4# configure terminal
SW4(config)# interface gi0/0
SW4(config-if)# description STATIC_TRUNK_TO_SW5_Gi0/2
SW4(config-if)# switchport mode trunk
SW4(config-if)# switchport trunk allowed vlan 10,20,30,40
SW4(config-if)# end

SW5# configure terminal
SW5(config)# interface gi0/2
SW5(config-if)# description STATIC_TRUNK_TO_SW4_Gi0/0
SW5(config-if)# switchport mode trunk
SW5(config-if)# switchport trunk allowed vlan 10,20,30,40
SW5(config-if)# end

On older multilayer-switch images that offer more than one encapsulation, insert switchport trunk encapsulation dot1q before switchport mode trunk on the two static-trunk interfaces. Many modern IOSvL2/Catalyst images support only 802.1Q and do not accept that command.

Step 5 - Save and verify

! Run on every switch
copy running-config startup-config
show vlan brief
show interfaces trunk
show interfaces switchport

! DTP-focused checks: run on SW2, SW3, and SW5
show dtp interface gi0/0
show dtp interface gi0/1
show dtp interface gi0/3

! Confirm MAC addresses are learned in the expected VLAN
show mac address-table dynamic
show mac address-table vlan 10
show mac address-table vlan 20
show mac address-table vlan 30
show mac address-table vlan 40

show interfaces trunk should show Gi0/0 on SW1 and SW4, and Gi0/0, Gi0/1, Gi0/3 on SW5 as trunking. It should also show VLANs 10,20,30,40 allowed and active. show vlan brief lists access ports only, so it normally does not list trunk ports under a VLAN.

End-to-end tests

! These pings must succeed (same VLAN across the trunks)
PC1> ping 10.1.1.8    # VLAN 10: PC1 to PC8
PC2> ping 10.1.1.6    # VLAN 20: PC2 to PC6
PC3> ping 10.1.1.7    # VLAN 30: PC3 to PC7
PC4> ping 10.1.1.5    # VLAN 40: PC4 to PC5

! This must fail (different VLANs and no inter-VLAN router)
PC1> ping 10.1.1.2

The first ping can lose one packet while ARP and MAC-address learning occur. Repeat it before declaring a fault.

Troubleshooting and debugging

Start with the non-disruptive show commands. Use live DTP debugging only briefly in a quiet lab because it can generate many console messages.

! 1. Confirm physical status and VLAN assignment
show interfaces status
show vlan brief
show interfaces gi0/0 switchport

! 2. Confirm each inter-switch link is actually trunking
show interfaces trunk
show interfaces gi0/0 trunk

! 3. Inspect the negotiated administrative and operational modes
show interfaces gi0/0 switchport
show dtp interface gi0/0

! 4. Watch DTP negotiation briefly (SW2/SW3/SW5 only)
terminal monitor
debug dtp events
debug dtp packets
undebug all

! 5. Trace forwarding and spanning-tree state for a VLAN
show spanning-tree vlan 10
show spanning-tree vlan 20
show mac address-table dynamic

! 6. Check for interface errors or an administratively shut port
show interfaces gi0/0
show running-config interface gi0/0

Common faults and fixes

Symptom: SW2--SW5 does not form a trunk
Check:   show dtp interface gi0/0 (SW2) and gi0/1 (SW5)
Fix:     SW2 must be dynamic auto and SW5 must be dynamic desirable.

Symptom: a VLAN is absent from show interfaces trunk
Check:   show interfaces trunk; show vlan id <vlan-id>
Fix:     create the VLAN on both switches and allow it on the trunk.

Symptom: same-VLAN PCs cannot ping
Check:   access-port VLAN, trunk state, allowed VLAN list, and MAC table.
Fix:     correct the access VLAN and confirm every path trunk carries that VLAN.

Symptom: different-VLAN PCs can never ping
Meaning: expected in this topology; a router or Layer 3 switch with SVIs is required
         for inter-VLAN routing.

Key takeaways

A VLAN is a separate Layer 2 broadcast domain. A trunk carries tagged traffic for multiple VLANs between switches. Static trunks are predictable and recommended for production uplinks; DTP is useful for learning but is usually disabled on production-facing ports. In this lab, VLAN membership—not the shared IP subnet—decides which PCs can exchange Layer 2 frames.
